# SEO and AI Search Foundation

## Overview
This phase establishes a robust SEO and semantic web foundation for LocalPages.ph, ensuring the directory is optimized for traditional search engines (Google, Bing) and AI search agents (Perplexity, ChatGPT, Gemini, etc.).

## Metadata Strategy
We utilize Next.js `generateMetadata` to inject dynamic, highly-contextual metadata across the application.
- **Homepage & Search**: Statically generated but highly relevant descriptions and titles.
- **Business Profiles**: Dynamically generated based on business data. Titles follow the pattern `[Business Name] - [Category] in [City]`, maximizing long-tail local search potential.
- **Social Sharing**: Fully populated Open Graph (og:title, og:description, etc.) and Twitter Cards for rich social previews.

## Structured Data Strategy (JSON-LD)
We generate dynamic Schema.org structured data to feed search engines exact entity parameters.
- **Type**: `LocalBusiness`
- **Injected Data**: Name, Description, Address (street, city, province, postal code), Telephone, Category (genre), URL, and `sameAs` links for social profiles and official websites.
- **Implementation**: The schema is injected via a `<script type="application/ld+json">` tag directly in the business profile Server Component.

## Sitemap & Robots Rules
- **Robots.txt**: Explicitly allows crawling of public pages (`/` and `/business/`) while strictly blocking administrative and authenticated routes (`/admin`, `/dashboard`, `/auth`). Points directly to our sitemap.
- **Sitemap.xml**: Dynamically generated by Next.js using `src/app/sitemap.ts`. It includes static priority pages (Home, Search) and dynamically injects all **Approved** businesses, ensuring new listings are rapidly discovered by crawlers.

## AI Search Readiness Standards
AI agents parse HTML fundamentally differently than classic crawlers, heavily relying on semantic structure.
- **Heading Hierarchy**: Strictly enforced one `<h1>` per page (the business name). Logical `<h2>` tags for sections (About, Products, Services) and `<h3>` tags for sidebar utilities (Contact Information, Business Hours).
- **Clean HTML**: Use of standard, un-obfuscated classes and readable layout trees.
- **Visible NAP Data**: Name, Address, and Phone Number (NAP) are distinctly separated and clearly labeled in the DOM, making extraction trivial for AI summarizing agents.

## Future Enhancements
- **IndexNow Implementation**: In future phases, we will integrate with the IndexNow API to proactively ping search engines the millisecond a business status transitions to `APPROVED`.
- **Dynamic Images**: Replace placeholder OG images with actual user-uploaded cover photos and logos once Firebase Storage is implemented.
